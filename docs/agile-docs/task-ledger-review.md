# 任务台账模板讨论结论

状态：已确认修订方向并纳入技能包；本文件仅保留维护依据，不是运行规则。

## 来源与问题

参考来源项目的任务台账规范、模板、配置中心迁移、设计系统迁移、商业增长及 CORS 发布收尾记录。
实际抽查发现：任务之外还存在摘要、独立待办、变更与日志；某些必要收尾藏在摘要中，单看任务勾选无法判断剩余工作。多个活跃台账超过 500 行，摘要也可能演变成历史流水。

首轮提案保留了独立“接续”区块。用户指出它仍需与任务表重复同步，容易漏更新；据此放弃该默认结构。

## 已确认取舍

- 固定内容收敛为稳定边界与唯一任务表，下一步从状态、依赖及当前备注判断。
- 所有影响本轮完成的工作进入表；人工确认和必要收尾不能藏在摘要。
- 剩余动作、阻塞解除条件和单任务现场附着在对应行；只有共享现场才使用可选区块。
- 依赖图按需使用，简单关系直接看依赖列；不强制维护图表两份关系。
- 不默认保留接续摘要、变化史和逐会话日志；重要证据与决定仍需可追溯。
- 一次进展通常只更新相应任务行，不能靠不断追加摘要绕过过期状态。
