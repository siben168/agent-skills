# 任务台账模板提案

状态：待讨论；本提案、模板与示例属于维护资料，尚未纳入运行时技能包。已确认的台账原则见 [任务台账规则](../../skills/agile-docs/references/task-ledgers.md)。

## 对照结论

参考来源项目 `.agents/tasks/templates/task-ledger.md`、活跃的模型能力登记台账和已归档的 CORS 发布收尾台账。仅分析结构，不重写原项目记录。

| 现有做法与实际问题 | 提议 |
|---|---|
| Current State 前置，便于恢复 | 保留简短“接续”，放在开头；Done 不再重复整张任务表 |
| Goal / Scope 已明确目标与范围 | 加上本轮完成条件与所属阶段，确保可以结束 |
| Checklist 有勾选，但难看出依赖与执行者 | 用一张任务表维护 ID、任务及完成条件、执行者、依赖、状态、证据 |
| 活跃台账在主要目标上线后仍继续收纳后续范围 | 原目标达成即关闭；新阶段另建并链接，不用无限扩大目标来保持活跃 |
| Decisions / Validation / Session Log 容易重复同一事实 | 稳定决定写回正式文档；证据挂任务；交接只保留影响接续的信息 |
| 执行细节不断追加，当前状态和历史混杂 | 原地更新当前状态，历史保留在 Git/既有证据入口；必要的变更摘要按实际需要保留 |
| 发布收尾台账有明确排除范围与终点 | 保留这种有界写法；具体环境恢复信息只写接续必需内容 |

## 一页表达四件事

1. **接续**：下一步和阻塞，必要时附工作现场。
2. **位置与边界**：属于哪个需求/阶段，本轮目标、完成条件和范围。
3. **任务关系与执行表**：有分支时给依赖图，任务表是执行事实的权威来源。
4. **范围变化与收尾**：仅在有变化或关闭时填写，不预置无限日志。

“一页”是阅读体验目标，不是页数或行数硬限制。小任务省略图和无用字段，不能为了套模板补出额外任务。

## 图与表怎么配合

- 所属路径展示全局位置，例如“产品平台 → 统一售后（PRD-002）→ 网页版实施”。不要凭空补出未确认的未来阶段。
- 任务依赖以表中“依赖”列为准；有并行或汇合时，用纯文本图作同源简述。简单顺序直接看表即可。
- 图只用任务 ID 表示结构，不复制完成状态、负责人或说明；任务更新时同步结构，发生不一致时先核对表。
- 仅当多份台账难以定位时，在项目已有入口添加按需求/阶段分组的链接，不再维护一张重复状态总表。
- 任务 ID 只在该台账内唯一，采用 T1、T2 等即可；新增递增，不重排已被引用的任务。跨台账依赖使用文件链接与任务 ID。

## 状态与责任

台账整体状态采用项目已有约定；没有约定时用 active、blocked、done、superseded。整体 blocked 表示本轮已无可推进任务；个别任务阻塞、仍能推进其他项时整体保持 active。取消任务时明确关闭原因，不能把未完成写成 done。

任务状态使用待办、进行中、阻塞、完成；取消或移出以原因注明。完成对应任务行的完成条件，不能以“代码写完”代替该行要求的验收通过。
执行者可为人、Agent 或明确角色；多人协作时明确主执行者，避免“大家负责”。未实际分配时写“待分配”，图上的并行关系也不代表自动授权启动多个 Agent。

## 元信息与命名

只保留状态、创建/更新日期及必要关联入口；项目已有 YAML frontmatter 时沿用，不再在正文重复一套。
文件命名沿用项目约定；无约定可用 `ENG-YYYYMMDD_short_name.md`，文档治理用 DOC、运营执行用 OPS。日期为创建日期，更新和归档不改变；同日用主题区分，创建前按目标查重。

## 防止范围与记录膨胀

- 在原目标内新增必要任务可以直接更新表；改变交付边界或完成条件先回到权威需求处理，不能只在台账补勾选项。
- 范围外发现只留简短去向；未立项就写待评估，不自动加入当前任务，也不预先指定执行者。
- 不强制逐会话 Session Log。需求变更、关键阻塞变化或交接约束确需追溯时保留简短摘要，完整过程指向已有 Issue/PR 或证据记录。
- 证据优先用提交、测试报告、PR/CI 或可保留的文件入口；短结论可写在表里。临时文件注明可能失效，不能作为关闭后唯一证据。没运行的检查明确写未验证。
- 关闭前核对完成条件与长期知识回收，保留结果和证据限制，更新状态并按项目约定归档；后续范围有自己的去向。
