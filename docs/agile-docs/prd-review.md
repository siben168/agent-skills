# PRD 模板提案

状态：待讨论；本提案及示例仅供技能维护，不属于运行时技能包。

## 对照结论

参考来源项目的 `docs/templates/001_prd.md`、PRD-100（CORS 来源匹配统一）和 PRD-084（官方社群与客服入口）。不改写来源项目的实际文档，不复制其业务资料。

| 原有内容或实际表现 | 提议 |
|---|---|
| Current Summary 能快速说明当前结论 | 保留为“当前结论”，只概括目标、关键取舍及适用边界；短文可与目标合并，不逐条重复正文 |
| 路径、类型、深度、负责人、创建/更新日期、版本表等元信息并列 | 默认保留必要的有效性说明、更新日期与关联入口；文件路径、作者和版本历史交给仓库；项目有明确需要时再补字段 |
| Progress 包含 Done / Next / Blocker | 改成阶段方向与交付结论，不记录下一项执行任务、任务负责人和任务阻塞流水 |
| 目标/非目标与范围表容易重复 | 合并为“问题、目标与范围”，只写影响判断的边界 |
| Full 要求固定故事句式、图、API/数据/监控等全部章节 | 改成按风险补充，不机械填写；图用于解释真实流程或状态，不装饰文档 |
| PRD-100 的契约和异常边界较清楚，但正文还包括大量发布与故障恢复过程 | 保留契约、验收标准和简短交付结论；具体过程归台账、发布记录或复盘，PRD 链接即可 |
| PRD-084 用“位置—内容—操作”表表达概要设计，验收覆盖登录和失败分支 | 保留这种具体表达；不用抽象用户故事替代实际行为；真实联系方式等配置引用其权威来源 |
| 每份 PRD 重复文档维护规则 | 规则留在 skill 或项目约定，PRD 不复制 |

PRD-100 虽标 Lite，但涉及多个服务与权限边界。不能按文档标签或字数判断风险；轻量只减少形式，不省略关键约束。

## 建议结构

采用一套结构，按内容裁剪；不要求每份文档声明 Lite / Standard / Full。
以下方括号为模板写作提示，实际填写后删除。不适用的可选章节直接移除。

```markdown
# [项目编号与需求名称]

[草稿时明确标记；当前文档按项目约定识别。]
更新：[日期]；关联：[必要的 ADR、权威契约、执行台账等入口]

## 当前结论

[简短说明本次要实现的结果、关键取舍和边界；短文可合并到下一节。]

## 1. 问题、目标与范围

[谁在什么场景遇到什么问题，本次希望达到什么结果。]
[包含的范围，以及容易被误纳入的非目标。]

## 2. 需求与概要设计

[用户或调用方流程、业务对象、关键规则、必要的异常与权限边界。]
[按实际需要选用文字、行为表、状态表或图；接口/数据契约已有权威来源时引用。]

## 3. 验收标准

[稳定的验收标识：在什么条件下，应得到什么可观察结果。]
[覆盖关键成功路径及适用的异常、权限、兼容等边界。]

## 4. 实施阶段（分阶段时使用）

[阶段、交付方向、该阶段完成后的能力边界；只记录已确认的阶段。]
[需要时补阶段交付/验收结论与证据入口；不放执行任务。]

## 5. 实现备注（需要时使用）

[简单方案的复用点、接口/数据影响、兼容与迁移约束。]
[复杂设计链接到对应 ADR 或关联材料；不罗列逐文件改动任务。]

## 6. 未决事项与风险（存在时使用）

[会影响范围、设计或验收的问题；说明影响及哪些部分可继续。]
[不能将尚未确认的建议写成已确认需求。]
```

## 几个需要明确的写法

**需求规则与验收标准不是重复。** 规则定义行为，验收说明如何证明行为成立；可用规则/AC 标识建立对应，不必维护两套同文内容。

**验收标准不是执行任务。** 用“未登录时只显示公开联系方式”表达结果，避免写成“修改登录判断代码”。默认不用待办勾选框；如果项目需要验收状态，可附简短结果及证据链接，不能变成开发进度表。

**实施阶段不是任务分解。** “先提供统一入口，再覆盖其余客户端”是阶段方向；“修改组件、补测试、提交发布”属于台账。单阶段小需求不必增加阶段表。

**有效性与交付状态分开。** 当前有效的 PRD 可以描述尚未实现的目标；标 Current 不代表已实现、已验证或已发布。只有必要时写交付结论，并注明证据边界。

**元信息从简。** 不强制文档负责人，也不禁止项目保留维护联系人；维护联系人不等于具体任务执行者。不新增一套独立版本表与 Git 历史重复。

**复杂度增加内容，不强制增加文件。** 按需补用户流程、接口、数据、监控、迁移和风险；当职责混杂或长度妨碍理解时拆分，保持入口和事实归属明确。

## 本轮讨论重点

建议先确认这三项：元信息是否足够精简；PRD 中的阶段与验收表达是否清晰；这套结构是否能同时容纳产品需求和工程需求。
确定结构后再把模板与代表性案例纳入技能包，并添加按需入口；本轮不推进 ADR 或台账模板定稿。
