# PRD 模板提案

状态：已确认并纳入技能包；本文保留对照依据，供技能维护。模板和写作规则以技能包中的文件为准。

## 对照结论

参考来源项目的 `docs/templates/001_prd.md`、PRD-100（CORS 来源匹配统一）和 PRD-084（官方社群与客服入口）。不改写来源项目的实际文档，不复制其业务资料。

| 原有内容或实际表现 | 提议 |
|---|---|
| Current Summary 能快速说明当前结论 | 保留为“当前结论”，只概括目标、关键取舍及适用边界；短文可与目标合并，不逐条重复正文 |
| 路径、类型、深度、负责人、创建/更新日期、版本表等元信息并列 | 默认保留必要的有效性说明、更新日期与关联入口；文件路径、作者和版本历史交给仓库；项目有明确需要时再补字段 |
| Progress 包含 Done / Next / Blocker | 改成阶段方向与交付结论，不记录下一项执行任务、任务负责人和任务阻塞流水 |
| 目标/非目标与范围表容易重复 | 合并为“问题、目标与范围”，只写影响判断的边界 |
| Full 要求固定故事句式、图、API/数据/监控等全部章节 | 改成按风险补充，不机械填写；图用于解释真实流程或状态，不装饰文档 |
| PRD-100 的契约和异常边界较清楚，但正文还包括大量发布与故障恢复过程 | 保留契约、验收标准和简短交付结论；具体过程归台账、发布记录或复盘，PRD 链接即可 |
| PRD-084 用“位置—内容—操作”表表达概要设计，验收覆盖登录和失败分支 | 保留这种具体表达；不用抽象用户故事替代实际行为；真实联系方式等配置引用其权威来源 |
| 每份 PRD 重复文档维护规则 | 规则留在 skill 或项目约定，PRD 不复制 |

PRD-100 虽标 Lite，但涉及多个服务与权限边界。不能按文档标签或字数判断风险；轻量只减少形式，不省略关键约束。
