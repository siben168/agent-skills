# ADR-001: 报表导出采用异步任务

状态：Draft，虚构案例，仅示范 ADR 与实现设计的边界；未实施、未验证。
更新：2026-11-08
示例编号属于独立虚构项目；文件名示例为 `ADR-001_async_report_execution.md`。
需求前提：本例假设产品已要求用户提交大报表后可离开页面，返回后查看结果；具体额度、保留期限和产品验收由该项目 PRD 维护。

## 当前决策（拟议）

导出接口只接受并记录任务，后台执行器负责计算与保存结果，前端查询任务状态后下载文件。复用现有数据库和对象存储，暂不引入独立消息队列。

## 1. 背景与约束

同步请求会把报表计算时长绑定到浏览器连接；用户离开页面后也难以判断是否完成。
假设本期并发较低，团队能维护现有数据库中的任务调度，但不希望为此新增一套消息系统。该假设需在实施前结合现有负载核实。

## 2. 决策与理由

- API 负责权限检查、请求校验和创建持久化任务；任务提交成功不等于文件已生成。
- 后台执行器领取任务并计算，文件保存在对象存储；数据库维护任务状态和文件引用。
- 任务查询和下载都重新检查访问权限；知道任务 ID 不等于有权访问结果。
- 本期采用数据库任务领取机制，以减少基础设施；业务任务记录不依赖某个执行进程的内存存活。

| 备选 | 取舍 |
|---|---|
| 延长同步请求超时 | 改动少，但没有解决离开页面后的结果恢复与任务追踪 |
| 数据库任务加后台执行器 | 复用现有设施，符合低并发假设；需要处理领取、超时与重复执行 |
| 新增独立消息队列 | 可独立扩展调度，但增加运行维护成本；出现明确吞吐瓶颈后再评估 |

## 3. 影响与代价

前端需要表达等待、处理中、成功和失败状态，调用方需要按任务 ID 查询结果。
系统增加任务清理和失败恢复责任；数据库扫描开销与领取延迟需要观测。若实际负载无法满足 PRD 的响应与完成时限，应重新评估调度方式。

## 4. 实现设计

### 职责与状态

API 创建任务时记录所属用户、请求参数快照和去重标识；参数在该次任务执行期间不随页面筛选变化。
同一用户与去重标识的重复提交只能返回同一任务；参数不同则返回冲突，不能误复用旧结果。

执行器通过数据库原子领取取得带版本的租约；任务由等待进入处理中，再进入成功或失败。租约到期的任务可被重新领取，超过既定尝试上限后终止并显示失败；具体重试参数在运行配置中单点维护。
旧执行器失去租约后，不能更新新一轮执行的状态。每次尝试写入独立文件对象，只有持有当前租约版本的执行器可以发布最终文件引用，避免旧执行覆盖已完成结果。

查询接口从数据库读取状态；下载接口确认权限与成功状态后提供受控文件访问。对象存储不作为任务状态的第二权威来源。
最终 API 字段和状态枚举在接口契约中维护；实施时补充真实契约链接，不在多个文档复制字段表。

### 失败、兼容与迁移

计算失败或上传失败不能标为成功；尚未被成功任务引用的尝试文件按清理策略回收。数据库状态发布失败时允许恢复，但不能让用户看到半成品。
新任务查询和下载能力必须先就绪，客户端才能切换到异步提交。切换期间保留旧同步入口，既有调用方不因新客户端上线而立即失效；旧入口停用范围由 PRD 另行明确。
停止接受新异步任务可以作为回退动作，但不能丢弃已经接受的任务；需要保留执行器和结果读取能力，直到存量任务按保留策略结束。

## 5. 验证要点

- 同一去重标识的并发提交只产生一个任务；参数冲突能被识别。
- 多个执行器不能同时持有同一有效租约；过期执行器不能发布或覆盖新结果。
- 进程在领取、上传或状态发布前后退出时，任务能恢复或明确失败，不永久停留在处理中。
- 未授权用户不能查询或下载他人的任务结果。
- 客户端切换及回退期间，已接受任务仍可查询和完成，旧入口保持约定的兼容行为。

以上是设计验证要求，不是已通过的结果。具体测试任务、执行者、提交与发布记录进入台账；产品完成时限和用户操作验收回到 PRD 核对。
