# ADR 与实现设计模板提案

状态：待讨论；仅供技能维护，尚未纳入运行时技能包。

## 对照结论

参考来源项目的 `docs/templates/002_adr.md`、ADR-018（请求 ID 中间件）和 ADR-045（能力与路由）。仅分析写法，不复制业务规则或修改来源项目。

| 参考中的做法 | 提议 |
|---|---|
| 原模板有背景、决策、备选方案、影响 | 保留这些核心问题；短决策可以合并章节，不强制备选方案数量 |
| 原模板默认标 Current | 新方案先标 Draft；只有已确认的决策才作为当前依据，不能用模板默认值代替确认 |
| ADR-018 明确约束适用范围，也说明哪些相邻情形不受该约束 | 保留适用边界，防止把局部修复泛化成整个项目的硬规则 |
| ADR-018 写清代价与应验证的不变量 | 保留“为何采用、接受什么代价、怎样判断实现遵守决策” |
| ADR-045 包含跨服务职责、接口行为与失败分支 | 放入实现设计，按需要细化；已有权威契约时链接，不复制另一套字段定义 |
| ADR-045 混有分支/提交、下一批任务和发布过程 | 这些归台账或发布记录；ADR 只保留影响理解的实现证据入口 |
| 原模板把 TODO 与阶段计划都指向 PRD | 阶段方向归 PRD，具体 TODO 和执行负责人归台账 |

## 什么时候使用

存在需要长期遵守的职责划分、技术选择或关键取舍时写 ADR。
简单实现方案继续放 PRD；只有实现步骤较多但没有架构取舍时，不强行为它创建 ADR。
一份 ADR 围绕一个连贯的决策主题，可包含必要的实现设计。跨主题或篇幅影响理解时拆成独立 ADR 或关联附件，不建立新的强制文档类型。

编号沿用 [文档编号与命名规则](../../skills/agile-docs/SKILL.md#文档编号与命名)：如 `ADR-001_async_report_execution.md`，标题为 `ADR-001: 报表导出采用异步任务`。

## 建议结构

方括号为写作提示，填写后删除；不适用的章节省略。

```markdown
# ADR-[编号]: [决策名称]

[拟议方案标 Draft；已确认决策按项目约定说明当前有效性。]
更新：[日期]；关联：[相关 PRD、既有决策和权威契约]

## 当前决策

[简短说明选择了什么、适用范围、最重要的约束；短文可与决策章节合并。]

## 1. 背景与约束

[要解决的技术问题，引用需求目标；影响选择的实际约束与证据。]

## 2. 决策与理由

[采用什么方案，职责如何划分，哪些约束必须保持，为什么。]
[有意义的备选方案及未采用原因；不为凑表格虚构备选。]

## 3. 影响与代价

[收益、接受的代价、对现有系统或使用方的影响；必要时说明重新评估的条件。]

## 4. 实现设计（需要时使用）

[模块职责、关键流程与状态、接口/数据所有权、失败处理。]
[兼容与迁移约束、必要的技术切换顺序及恢复边界。]
[已有契约引用其权威来源；长细节拆附件。]

## 5. 验证要点

[证明实现遵守决策的关键不变量和验证方式，不重复 PRD 的产品验收标准。]
[实际验证结果和部署事实链接执行记录，不在此维护任务勾选。]

## 6. 未决事项（存在时使用）

[尚待确认的设计问题、影响及适用边界；不能把建议写成已确认决定。]
```

## 设计与任务的分界

| 应保留在 ADR 的设计 | 应放在台账的执行 |
|---|---|
| 消费者必须兼容新旧字段后，生产者才能切换，否则请求会失败 | 升级哪个服务、谁执行、是否完成 |
| 旧记录必须能按既有格式读取，迁移失败时保留原值 | 运行迁移命令、记录批次结果、完成验证 |
| 重复请求不得产生第二个任务；用并发请求验证 | 编写具体测试、运行测试并记录证据 |

ADR 中的验证要点约束设计正确性；PRD 的验收标准约束交付效果，两者引用关联。技术切换前提可以有顺序，不能由此扩展为排期和具体任务清单。

## 修订与完成后的维护

同一决策的澄清与兼容细化保留编号；改变核心选择时创建替代 ADR，并建立替代关系。按项目约定保留历史理由，不静默覆盖成“从未选择过旧方案”。
实现完成后保留稳定的职责、契约和约束。迁移过程已结束且不再适用的细节移入历史记录，正文说明当前适用结论。
未决事项解决后更新相应决策，不累积对话审批流水。Current 表示决策有效，不表示所有服务已经实现或上线。

## 填写案例与讨论点

[报表导出采用异步任务](adr-example.md) 展示同一份 ADR 如何承载决策与实现设计，包含数据职责、失败处理、迁移边界和验证要点；为虚构示例，未实施或验证。

本轮重点是确认：这样的实现设计深度是否足够；“技术切换约束”和“具体执行任务”的边界是否清楚。短 ADR 可只保留背景、决策理由、代价与验证要点，不要求按示例扩写。
