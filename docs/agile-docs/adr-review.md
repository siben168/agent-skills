# ADR 与实现设计模板提案

状态：已确认并纳入技能包；本文仅保留维护对照依据，运行规则以技能包为准。

## 对照结论

参考来源项目的 `docs/templates/002_adr.md`、ADR-018（请求 ID 中间件）和 ADR-045（能力与路由）。仅分析写法，不复制业务规则或修改来源项目。

| 参考中的做法 | 提议 |
|---|---|
| 原模板有背景、决策、备选方案、影响 | 保留这些核心问题；短决策可以合并章节，不强制备选方案数量 |
| 原模板默认标 Current | 新方案先标 Draft；只有已确认的决策才作为当前依据，不能用模板默认值代替确认 |
| ADR-018 明确约束适用范围，也说明哪些相邻情形不受该约束 | 保留适用边界，防止把局部修复泛化成整个项目的硬规则 |
| ADR-018 写清代价与应验证的不变量 | 保留“为何采用、接受什么代价、怎样判断实现遵守决策” |
| ADR-045 包含跨服务职责、接口行为与失败分支 | 放入实现设计，按需要细化；已有权威契约时链接，不复制另一套字段定义 |
| ADR-045 混有分支/提交、下一批任务和发布过程 | 这些归台账或发布记录；ADR 只保留影响理解的实现证据入口 |
| 原模板把 TODO 与阶段计划都指向 PRD | 阶段方向归 PRD，具体 TODO 和执行负责人归台账 |
