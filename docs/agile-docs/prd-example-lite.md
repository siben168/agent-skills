# PRD-001: 导出日期范围校验

状态：虚构草稿，仅用于讨论 PRD 写法；未实施、未验证。
示例编号仅属于虚构项目，不占用来源项目的编号；正式文件名示例为 `PRD-001_export_date_validation.md`。
更新：2026-11-08

## 1. 问题、目标与范围

后台导出允许提交结束日期早于开始日期的请求，用户只能在等待后发现失败。目标是在提交前给出明确提示，并让直接调用接口的客户端受到相同校验。

本次只增加日期范围校验，沿用已有身份验证、导出字段和日期解析方式。不增加最长导出天数限制，也不重做导出任务系统。

## 2. 需求规则

- R1：开始、结束日期继续使用现有必填与格式校验；校验通过后，开始日期必须早于或等于结束日期。
- R2：两日期相等时，沿用现有单日导出语义，不改变时区或日期端点处理。
- R3：前端发现开始日期晚于结束日期时，在日期区域显示纠正提示，不提交请求；用户修正后可再次提交。
- R4：接口独立执行相同范围校验；非法范围返回既有参数错误响应结构，不创建导出任务。

## 3. 验收标准

| 标识 | 条件 | 预期结果 |
|---|---|---|
| AC1 | 页面选择开始日期晚于结束日期并提交 | 显示纠正提示，不发出导出请求 |
| AC2 | 直接向接口提交非法日期范围 | 返回既有参数错误，不创建任务 |
| AC3 | 将非法范围修正为有效范围后再次提交 | 可进入原有导出流程，不残留错误阻止提交 |
| AC4 | 两日期相等 | 可进入原有单日导出流程，日期处理语义不变 |
| AC5 | 日期缺失或格式错误 | 沿用原有错误处理，不误报为范围倒置 |

验证覆盖前端行为、接口参数校验及有效请求回归；实际结果在实施后记录，本文不预先标记通过。

## 4. 实现备注

复用现有日期解析和参数错误构造方式；前端校验用于即时反馈，接口校验保证请求约束。不新增数据表或修改导出任务状态。
