# agile-docs 场景试用

维护者评估材料，不属于运行时包。项目原始记录与具体补丁留在应用项目，这里仅保存可迁移的行为发现、修订和验证限制；不复制执行台账或规则全文。

## 已完成的来源项目案例（2026-11-10～12）

方式：维护者在当前会话手工读取技能，在独立工作树修改真实文档，并按需核对源码 / 既有证据。入口试用起点为 `3531916`，本轮治理收尾运行时基线为 `6e6147b`。不是独立盲测，未验证安装后的发现或跨工具调用。

| 场景与观察 | 处理与通用结论 | 验证及限制 |
|---|---|---|
| 改名、退役后的入口维护遗漏相反状态 | 原“未暴露通用缺陷”判断过强；在定位依据步骤澄清冲突范围及未决状态，不凭文件新旧选事实 | 修正入口与引用，后续复查保留三类来源差异；无独立生产证据 |
| 台账摘要、待办和日志重复维护 | 真实 active 台账改为稳定边界与唯一任务表；用户反馈后去掉必填执行者列，指定角色按需标明 | 能从任务行辨认依赖、下一动作与阻塞解除条件；实际后续更新成本待验证 |
| PRD 与执行进度混合，草稿前提受后续实现影响 | PRD 留需求 / AC / 阶段，执行与跨账依赖归台账；源码核对不替代业务验收，也不将建议当作批准需求 | 保留 AC 范围、未决项与已有能力边界；未开展业务实现 |
| AC 表达不明确 | 行为类采用 Given / When / Then 思路，技术约束可简写；不引入 BDD 工具或放宽验收目标 | 规则、模板与示例同步，真实文档局部等义调整；未做功能验收 |
| AC 核对另建报告造成重复 | 删除报告，短结论与证据就近回任务行；入口补最小留存判断 | 后续 ADR 案例复用，未新增历史副本；不代表业务交付 |
| ADR 分开设计 / 执行后仍难读 | 经独立可读性评审，先讲选择、职责和数据边界，再呈现精确字段；修正“难读即拆分”的倾向 | 重排真实 ADR，保留有效约束和 Draft 边界；技术实现仍待推进 |
| 长指南混有已完成迁移步骤 | 主体保留现行操作，历史归已有台账 / Git；恢复前提按现存资源核对 | 固定源码对照与合成检查，未执行部署；观察日期已过不等于取得验收证据 |
| 已取消事项和缺证据事项混写 | 已退役服务的演练用取消表达，其他凭据类事项保留待核实；相邻任务的完成证据不能外推 | 现有规则已覆盖，不新增运行时条目；未调查生产或执行轮换 |
| 项目旧规范会要求补回重复章节 | 项目指令、模板与规范统一采用新职责；临时目录的 Git 忽略差异留项目约定 | 已完成案例及规范收敛，不等于全项目文档已迁移；不向通用包加入项目路径 |

## 候选版前整包检查（2026-11-13）

检查范围：全部运行时规则、模板、案例及七份维护文档。16 个运行时文件分别承担入口、6 份按需规则、4 份模板和 5 份案例；每个都有调用入口与独立用途，未为了减少文件数把条件性内容塞回入口。

五份已采纳的模板提案不再独立维护，其必要取舍归[设计共识](../agile-docs-design.md)，完整历史在 Git `1bc203c`；本文件去掉重复提案、规则摘录和已过期的“下一步”。入口的台账摘要、编号兼容说明以及指南中的重复编号提示同步精简，规则仍由对应权威位置承载。

本次是内容、结构、包内引用与格式检查，不宣称已完成实际安装调用。后续采用顺序为固定候选版本 → 本地安装 → 新会话小范围调用 → 全项目清单与分批治理 → 最终回归 → GitHub 发布；进度只在应用项目台账维护。

## 首次本地安装调用（2026-11-13）

候选 rc.1 固定 `c35ee8f`，从提交导出完整运行时包到 Codex 本地技能目录，安装内容逐字节一致。独立 Codex 任务显式调用技能并提供安装路径，报告目录可见、按需读取台账规则和模板，产出真实业务尾账及归档入口修复。首稿备注膨胀并漏修接续指向，经过主任务反馈和复核后通过；该问题已有简洁与引用规则覆盖，本轮不扩充运行时包。

本例证明了带明确路径的显式调用及经复核的文档产出，未验证无提示自动触发、一次生成质量或全项目覆盖。任务 ID、校验值、具体产物及执行顺序留应用项目台账。
