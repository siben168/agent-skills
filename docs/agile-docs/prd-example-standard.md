# PRD-002: 统一售后联系入口

状态：虚构草稿，仅用于讨论 PRD 写法；未实施、未验证。
示例编号仅属于虚构项目，不占用来源项目的编号；正式文件名示例为 `PRD-002_unified_support_entry.md`。
更新：2026-11-08

## 当前结论

本期将分散的售后入口收敛到一个联系页面，按登录状态展示不同联系渠道。页面行为由本文定义，实际联系方式由产品已有联系配置维护。

## 1. 问题、目标与范围

用户遇到账号或付款问题时，需要在不同页面寻找联系方式，部分页面展示的信息已经不一致。

目标是让用户从固定入口找到可用联系方式，并在复制或图片加载失败时仍能完成联系。
本期覆盖网页版桌面和手机布局；复用现有导航与身份状态。不增加工单系统、自动客服、会员权益或响应时限承诺。

## 2. 需求与概要设计

### 入口与流程

个人菜单保留一个“售后联系”入口，进入公开可访问的联系页面。
未登录用户可以使用公开邮箱，也可以登录；登录完成后返回联系页面。页面不增加第二套登录流程。

### 页面状态与行为

| 状态或场景 | 页面展示与行为 |
|---|---|
| 身份加载中 | 显示公开邮箱；暂不展示专属联系区，避免错误闪现 |
| 未登录 | 显示公开邮箱和登录入口 |
| 已登录 | 显示公开邮箱，以及配置中可用的联系账号和二维码 |
| 联系账号或二维码未配置 | 隐藏对应操作，保留邮箱；不放假链接或占位二维码 |
| 复制成功或失败 | 分别提示结果；失败时提供可选中的文字供手动复制 |
| 二维码加载失败 | 说明图片不可用；已有联系账号仍可读取和复制 |

身份加载中与未登录时不请求二维码图片。登录限制仅是页面展示规则，不把公开静态资源当作秘密存储。
二维码按原图比例展示；手机页面应能完整查看内容和使用操作，不依赖横向滚动。
实际邮箱、联系账号和图片地址统一读取已有联系配置，本文不复制具体值。

## 3. 验收标准

| 标识 | 条件 | 预期结果 |
|---|---|---|
| AC1 | 桌面和手机用户从个人菜单访问 | 只有一个售后入口，进入相同联系页面 |
| AC2 | 身份加载中或未登录 | 邮箱可用，不显示联系账号、不请求二维码 |
| AC3 | 从联系页面登录成功 | 返回联系页面，展示已配置的登录后渠道 |
| AC4 | 联系配置缺项 | 不出现假值或失效占位操作，邮箱仍可用 |
| AC5 | 复制失败或二维码加载失败 | 用户得到准确反馈，并可通过现有文字联系方式继续联系 |
| AC6 | 使用窄屏页面 | 联系信息与主要操作可见，二维码比例正确，无横向滚动依赖 |

以页面状态和交互检查验证上述结果；本地模拟登录只能证明页面分支行为，真实登录返回路径需在适用的联调环境验证。发布事实另行记录，不能用本地通过替代已发布。

## 4. 实现备注

复用现有身份状态与登录返回机制，联系信息使用共享组件读取统一配置。
不新增后端业务接口、数据表或账号权限。若实施中发现现有登录流程不支持返回来源页，应先确认是否需要扩大需求范围。
