# agile-docs 设计共识与模板讨论计划

状态：基础规则、PRD 与 ADR 模板已确认；正在讨论任务台账模板，其余模板和跨项目/跨工具试用尚未完成。

本文件面向技能维护者，保存已确认的设计边界和后续讨论入口，不属于运行时技能包。运行规则以 [SKILL.md](../skills/agile-docs/SKILL.md) 及其按需引用为准，不在此复制另一份规则正文。

## 来源与已确认方向

本技能从 AIDesk 项目长期实践中提炼，并经用户讨论修订，目标是适配 OPC、小团队及人/Agent 协作的敏捷研发。

已确认的设计选择：

- 非常小的 bug、样式、文案可以跳过需求设计和技术方案设计。
- PRD 只表达阶段与方向，不承载具体执行任务及任务负责人；台账承担可完成的任务项。
- 一个事实有一个权威维护位置；同主题可以有不同职责的文档。
- 减少文档类型；简单实现方案放 PRD，复杂且涉及架构决策的方案可放 ADR 章节。
- 长文档必须被识别、简化或拆分；影响理解的长文档只有经用户同意才保留。
- 台账要显示整体位置和任务依赖，并限制范围、日志体积和生命周期。
- 通用规则、项目约定和案例历史分开；回流必须控制技能体积。

来源项目的目录、编号、云平台和服务结构不构成通用要求。现有模板是参考输入，不直接复制为定稿。

## 模板讨论顺序

| 顺序 | 对象 | 来源项目参考 | 重点讨论与预期产出 |
|---|---|---|---|
| 1 | PRD | `docs/templates/001_prd.md`；选择一个小需求和一个常规需求对照 | Lite/常规深度如何裁剪；概要设计如何嵌入；用阶段方向替换具体任务；确定简单实现备注边界 |
| 2 | ADR 与复杂实现设计 | `docs/templates/002_adr.md`；选择一个包含关键取舍的实例 | 长期决策和本次实现设计如何分节；哪些细节拆附件；移除执行进度 |
| 3 | 任务台账 | `.agents/tasks/templates/task-ledger.md`；选择一个跨会话实例 | 位置图、依赖、执行者、完成条件、证据和接续如何最简表达；如何防止范围和日志膨胀 |
| 4 | Guide / Runbook | `docs/templates/003_guide.md` | 前置条件、步骤、预期结果、失败处理和恢复，如何按风险裁剪 |
| 5 | 研究材料与归档 | `docs/templates/004_tmp_research.md`；选择一次已采纳研究 | 是否需要独立模板；结论如何晋升；过期内容如何指向替代入口 |

来源路径相对于来源项目根目录，仅用于维护讨论，不是本仓库的运行依赖。例子纳入技能包前需改写为自包含的通用案例。

## 每个模板的讨论方法

1. 对照原模板与一份实际文档，找出无用字段、缺失信息和重复维护点。
2. 先确认读者必须回答的问题，再确定章节与字段；不为形式保留空章节。
3. 写出最小模板，并用一个普通场景填写；必要时另给复杂场景的增补方式。
4. 检查是否违背已确认职责、是否有第二事实源、能否快速理解当前结论与行动。
5. 用户确认后加入技能资源并添加按需入口，不一次性批量定稿全部模板。

## 后续验证

模板稳定后，以微小修复、常规需求、跨模块设计、任务接续、范围外问题和长文档治理检验行为。
随后在不同目录结构的项目和目标工具中试用，依据实际问题做最小修订；验证记录留在维护材料或 PR 中。
