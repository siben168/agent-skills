# agile-docs 设计共识

面向技能维护者，不属于运行时包。规则以 [SKILL.md](../skills/agile-docs/SKILL.md) 及其按需资源为准；真实试用及限制见[场景试用](agile-docs/scenario-trials.md)。本文件只保留设计来源、取舍理由和资源入口，不维护另一套任务进度。

## 定位与边界

从 AIDesk 长期实践提炼，面向 OPC、小团队及人 / Agent 协作的敏捷研发。目标是减少定位依据、恢复任务和维护一致性的成本；来源项目的目录、技术栈、云平台和局部流程不成为通用要求。

文档治理不能代替业务验收，也不能把每次检查变成新报告。项目原始资料留应用项目，只有能改变通用判断的规则回流技能；本地安装、调用和全项目采纳的执行进度由应用项目的台账维护。

## 保留的设计取舍与入口

| 对象 | 选择依据 | 当前资源 |
|---|---|---|
| PRD | 原模板字段、深度标签和进度表过多；保留目标行为与可判定 AC，以具体流程表达概要设计，元信息按需 | [写作规则](../skills/agile-docs/references/prd.md)；含模板与轻量 / 常规示例 |
| ADR | 长期选择与必要实现设计可以共存；按决策、理由、职责再到细节阅读，不因复杂就机械拆文档 | [写作规则](../skills/agile-docs/references/adr.md)；含模板与实现设计示例 |
| 台账 | 原接续摘要仍需与任务表同步，试用中的“待分配”也无实际价值；采用唯一任务表，指定角色按需写备注 | [台账规则](../skills/agile-docs/references/task-ledgers.md)；含模板与带依赖 / 阻塞的示例 |
| Guide / Runbook | 关注操作目标、前提、结果和恢复；不另设部署运维类型，已有字段标准不强改成步骤表 | [指南规则](../skills/agile-docs/references/guide.md)；含统一模板与示例 |
| 研究与归档 | 独立研究按用途留存，采纳结论进入权威位置；不增加研究类型、强制模板或隐藏任务清单 | [研究与归档](../skills/agile-docs/references/research-archive.md) |

编号、最小留存及篇幅治理只在技能入口维护；图用于解释真实关系，不作为必填装饰。运行时只包含入口、按需规则、模板和虚构案例，没有来源项目路径或发布流程依赖。
