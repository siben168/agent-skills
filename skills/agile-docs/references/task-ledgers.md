# 任务台账规则

使用 [最小模板](../assets/task-ledger.md)，必要时参考 [填写案例](examples/task-ledger.md)。默认只有稳定边界和唯一任务表；不强制新增接续摘要、下一步清单、阻塞总表或会话日志。既有项目有明确格式要求时沿用，指出重复维护成本，不擅自重构无关台账。

## 创建与边界

跨会话、需要交接或用户要求跟踪时才创建。先查找同目标的活跃台账，已有则接续。单次能完成的任务通常不建。
开头简短说明关联依据、所属需求/阶段、本轮目标、完成条件与必要边界。需求细节引用权威 PRD/ADR，不复制一套；没有文档时引用用户确认的目标来源，不虚构文件。
元信息只保留状态、创建/更新日期与关联入口；已有 YAML frontmatter 则沿用，不在正文重复。
命名沿用项目约定；无约定可用 `ENG-YYYYMMDD_short_name.md`，文档治理用 DOC、运营执行用 OPS。日期为创建日期，归档不改名；同日用主题区分，按目标查重。

## 唯一任务表

任务表维护：稳定 ID、任务及完成条件、执行者、依赖、状态、当前备注/证据。

- 所有影响本轮完成的工作都必须进入任务表，包括范围内的人工确认、联调和必要收尾；不能藏在摘要或日志中。
- 任务应可执行、可判断完成，不用“持续优化”代替有界工作；过大的任务在确需独立推进时拆分，不把每个操作动作都建成任务。
- 执行者可为人、Agent 或明确角色；多人协作明确主执行者，未分配则标待分配，不虚构承诺。
- 状态通常用待办、进行中、阻塞、完成；取消或移出注明原因，不标成完成。完成对应本行完成条件与验证结果，不以“代码写完”代替验收通过。
- 剩余动作、阻塞原因和解除条件就近写在本行备注。备注维护当前结论，不按日期不断追加执行历史。
- 证据优先链接提交、报告、PR/CI 或可保留文件；短结果可直接写在表中。未运行的检查写未验证，临时路径不能成为关闭后唯一证据。
- ID 在本台账内唯一，如 T1、T2；新增递增，不重排已被引用的 ID。跨台账依赖带文件链接和任务 ID。

任务依赖以表中依赖列为准。只有复杂分支确实难以理解时，才补依赖图作同源简述，不复制状态和负责人。简单顺序省略图；任务结构变化时同步图。
所属路径用一行表达全局位置；多份活跃台账确实难定位时，在已有入口按需求/阶段列链接，不维护另一张状态总表。

## 从任务表恢复工作

1. 读取目标与完成条件，核对正在进行的任务及其备注，确认关键代码/环境前提仍成立。
2. 继续可推进的进行中任务，再看依赖已满足且无阻塞的待办。多个任务可执行时，按用户优先级或约定顺序选择，不强行指定唯一下一步。
3. 依赖完成不等于外部操作已获授权；遵循当前任务执行边界。并行依赖图也不代表已获准启动多个 Agent。

不另维护“下一步”“Done”“Blocker”摘要来复述任务表。单个任务的分支、测试现场等附在该行；只有多个任务共享且影响接续的现场信息，才使用可选“工作现场”区块。
旧记录的“已部署”不证明当前环境仍一致；现场信息不包含凭据或隐私。

## 最少更新动作

- 开始、阻塞或完成任务时，更新对应任务行及必要的更新时间；交接前核对本次实际改动对应的行，不重写整个台账。
- 稳定设计变化回写 PRD/ADR；任务表链接结果。完整执行过程留在已有报告、PR/CI 或必要专项记录中，不强制为每次工作生成日志文件。
- 原目标内的必要工作可以增补任务；改变交付边界或完成条件时先更新权威需求，不能通过加任务悄悄扩大范围。
- 范围外发现归对应需求或 backlog，未立项则标待评估；台账至多保留简短去向，不发展成第二个待办池。
- 不默认保留范围变化史或逐会话日志。必须追溯的决定保留来源链接与必要摘要，其余可通过 Git 或已有记录回溯；压缩前保留仍有效的约束和证据。

## 关闭与归档

整体状态沿用项目约定；缺省用 active、blocked、done、superseded。个别任务阻塞但其他项可推进时保持 active；本轮无可推进工作且仍有目标未达成时才标 blocked。取消时注明关闭原因，不冒充完成。
关闭前核对本轮完成条件和所有必要任务，将长期知识写回正式文档，保留验收限制及范围外事项去向；不能只因全部现有勾选完成就判定整体结束。
按项目约定归档并修复链接。被替代时说明替代关系；新阶段另立有界台账并关联，不把已完成台账变成永久待办池。
