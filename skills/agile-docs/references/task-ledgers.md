# 任务台账规则

本文件规定台账必须表达的信息和维护方式，不固定最终模板版式。沿用项目已有台账，按需补齐缺失信息。

## 创建与边界

跨会话、需要交接或用户要求跟踪时才创建。先查找同目标的活跃台账；已有则接续。

开头简短说明：

- **关联依据与位置**：权威 PRD/ADR 链接，所属需求与实施阶段。
- **本轮目标和完成条件**：本次执行的终点；引用需求验收标准，不复制一套。
- **范围边界**：本轮包含什么，以及容易被误纳入的相邻事项。

任务范围由目标限定，不因持续发现问题而无限增加。必要的新任务可在既定范围内增补；改变目标、交付边界或完成条件时，应先按需求变更处理。
范围外事项只记录简短去向，转到相应需求或后续事项；不能默认已获准执行，也不必为每个发现立即新建文件。

## 让逻辑可见

同时表达两种关系：所属需求/阶段的归属关系，以及本轮任务的依赖关系。

- 顶部用一行所属路径和简短阶段序列定位当前工作。
- 存在分支、并行或汇合时，用任务 ID 表达依赖图；简单顺序可直接使用依赖列。
- 图仅表达结构，完成状态只在任务表中维护。任务增删或依赖变化时同步结构，避免悬空 ID。
- 默认用普通文本；工具支持且更清楚时可用 Mermaid，不要求专用白板或服务。
- 多份活跃台账确实难以定位时，可建立按需求和阶段分组的链接导航；不手工复制各台账状态。

## 一张任务表承担执行事实

任务表表达：稳定 ID、具体任务及完成条件、执行者、前置依赖、状态、必要的证据链接。

- 任务是可执行和可判定完成的工作，不用“持续优化”“后续完善”充当有界任务。
- 执行者可为人、Agent 或明确的角色。尚未分配则标待分配，不能假设某人已承诺。
- 通常采用待办、进行中、阻塞、完成即可；项目已有等价状态时直接沿用。取消或移出任务时简注原因，不伪装为完成。
- 无前置依赖、无阻塞、无需证据附件时简写，不生成无用章节。
- 完成标记对应完成条件和验证结果；未验证的实现不能标成验收通过。
- 阻塞项写清阻塞原因及解除条件，不只写“等待”。

PRD 只保留阶段方向与阶段交付/验收结论，不能同步复制这张执行任务表。
任务依赖只在一个位置权威维护；依赖图是同源简述，不成为另一套独立计划。

## 简短交接，不记录聊天流水

交接只需让下一位执行者知道：下一步动作、必要工作现场、阻塞、未决范围变更以及新增证据。
工作现场可以包含相关分支、提交、环境和恢复入口，但只保留接续必需的信息，不记录凭据或隐私。

执行过程中：

1. 更新实际发生变化的任务状态、证据和下一步。
2. 将改变设计的稳定决定写回 PRD/ADR；台账保留摘要和链接。
3. 仅记录影响后续执行的决策、阻塞变化与验证结论；不按每次对话无限追加日志。
4. 历史记录开始妨碍接续时，提炼当前状态，将已结束阶段的必要证据转为可追溯链接。

恢复工作时，先读目标、任务表和下一步，再核对必要的代码/环境前提。旧记录中的“已部署”等事实不自动证明当前环境仍相同。

## 关闭

核对本轮完成条件，将长期有效内容沉淀回正式文档，保留验证限制和范围外事项去向。
按项目约定关闭或归档台账，并修复相关链接。被新目标替代时说明替代关系，不标成已完成。
新阶段创建独立的有界台账并链接前后关系，不将已经完成的台账变成永久待办池。
